# H2 — Pins: the inspector

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** A pin can be configured from the panel — the offset it holds is a real
row, X and Y show where the node actually is, and one click on Figma's 9-point
widget sets the pin without the child jumping.

**Architecture:** The four offset props have no scene field (ADR 0011 §2), which
decides everything here. They cannot render as ordinary rows, because
`editable.ts` calls an unmapped prop read-only; and they cannot commit through
the scene, because `scenePropFor` stops them and the write would vanish. Both
have precedents in this file already — the alias-paint branch in `onCommit`
routes structurally for exactly this reason. X and Y become the *resolved*
numbers, handed down from the canvas the way `exportBounds` already is, and
typing one writes the offset through a single conversion, `pinWrites`.

**Tech Stack:** Vue 3 (`<script setup>`), TypeScript, Vitest, `@uidx/schema`
for `PIN_PROPS` / `Pin` / `resolvedBox`.

**Spec:** [2026-08-29-pins-and-constraints-design.md](../specs/2026-08-29-pins-and-constraints-design.md) §4 and §5
**ADR:** [0011](../../decisions/0011-pins-a-child-states-its-offset.md)
**Depends on:** H1, shipped 2026-08-29 (`613c2fc`…`0cb13b1`).

## Global Constraints

- **Node 22 for every test run.** The default `node` is v18 and the suites fail
  with `ERR_REQUIRE_ESM`:
  `export PATH="$HOME/.nvm/versions/node/v22.15.0/bin:$PATH"`.
- **Commit to `main` directly.** No worktree, no feature branch.
- **Run `npx prettier --write <files>` before every commit.** CI checks it.
- **A pin write must never take the scene route.** `emit('commit', …)` reaches
  the file through `applyProp`, which derives the patch from the scene graph —
  and the graph never holds `right`. Pin writes go through `emit('patches', …)`,
  the same branch fills and strokes take when an alias is in play.
- **The panel never computes geometry.** The resolved box comes from the canvas
  through a prop, as `exportBounds` does. A panel that measures is a second
  answer to a question the scene graph already owns.
- **`SCALE` stays out.** The widget offers `MIN`/`CENTER`/`MAX`/`STRETCH` only;
  `uidx check` refuses `SCALE` (UIDX136) and H5 owns it.

- [ ] **Step 3: Write `pin-writes.ts`**

```ts
import type { Box, Pin, PinAxis } from '@uidx/schema'

/**
 * What a settled gesture writes for a pinned node — the inverse of H1's
 * `resolvedBox` (ADR 0011 §2).
 *
 * In the shape `position-writes.ts` and `resize-writes.ts` established: a
 * gesture says everything it means, in one envelope. Switching an axis from
 * MIN to MAX writes `right` *and* removes `x`, so the child does not jump and
 * the file never holds both — which `uidx check` would refuse anyway (UIDX134).
 *
 * Both axes convert every time. A caller that converted one would leave the
 * other saying something the new pin contradicts, and the failure would be a
 * check error on a file the author never typed into.
 *
 * Rounded, because a converted offset is a number a person then reads and
 * scrubs: 15.999999999999998 in a diff is noise nobody chose.
 */
export interface PinWrites {
  fields: Record<string, number>
  removals: string[]
}

/**
 * A node's resolved box and the box it is pinned inside — exactly the pair
 * `pinWrites` takes, and what the canvas hands the panel (Task 3).
 */
export interface PinFrame {
  box: Box
  parent: { width: number; height: number }
}

const round = (n: number): number => Math.round(n)

/** One axis, named by the props it may write, so the two cannot drift. */
function axisWrites(
  constraint: PinAxis,
  near: number,
  size: number,
  parent: number,
  props: { near: string; far: string; centre: string; size: string },
): PinWrites {
  const all = [props.near, props.far, props.centre]
  const keep = (...names: string[]): string[] => all.filter((n) => !names.includes(n))

  switch (constraint) {
    case 'MAX':
      return { fields: { [props.far]: round(parent - near - size) }, removals: keep(props.far) }
    case 'STRETCH':
      return {
        fields: { [props.near]: round(near), [props.far]: round(parent - near - size) },
        // The size is the pin's answer now, so the file must stop stating it.
        removals: [...keep(props.near, props.far), props.size],
      }
    case 'CENTER':
      return {
        fields: { [props.centre]: round(near + size / 2 - parent / 2) },
        removals: keep(props.centre),
      }
    default:
      return { fields: { [props.near]: round(near) }, removals: keep(props.near) }
  }
}

export function pinWrites(
  pin: Pin,
  box: Box,
  parent: { width: number; height: number },
): PinWrites {
  const h = axisWrites(pin.horizontal, box.x, box.width, parent.width, {
    near: 'x',
    far: 'right',
    centre: 'centerX',
    size: 'width',
  })
  const v = axisWrites(pin.vertical, box.y, box.height, parent.height, {
    near: 'y',
    far: 'bottom',
    centre: 'centerY',
    size: 'height',
  })
  return { fields: { ...h.fields, ...v.fields }, removals: [...h.removals, ...v.removals] }
}
```

- [ ] **Step 3: Expose the frame from the canvas**

In `CanvasPane.vue`, beside `exportBounds`:

```ts
/**
 * The node's resolved box and the box it is pinned inside.
 *
 * The panel cannot work either out. A pinned node's `x` is the resolve pass's
 * answer and appears in no attribute (ADR 0011 §2), and the parent's size is
 * whatever layout settled on. Measured here for the same reason
 * `exportBounds` is, and recomputed by the shell on selection or document.
 */
function pinFrame(address: string): PinFrame | null {
  const graph = editor.graph
  const id = sceneIdFor(address)
  const node = id ? graph?.getNode(id) : undefined
  const parent = node?.parentId ? graph?.getNode(node.parentId) : undefined
  if (!node || !parent) return null
  return {
    box: { x: node.x, y: node.y, width: node.width, height: node.height },
    parent: { width: parent.width, height: parent.height },
  }
}
```

and add `pinFrame` to `defineExpose`.

function displayValue(name: string, authored: JsonValue): JsonValue {

`patchesFor` is a small local helper turning a `PinWrites` into the envelope —
an `add` where the attribute is absent, a `set` where it is present, and a

```ts
function patchesFor(address: string, writes: PinWrites): UidxPatch[] {
  const attrs = active.value?.attrs ?? {}
  const out: UidxPatch[] = Object.entries(writes.fields).map(([prop, value]) => ({
    op: attrs[prop] === undefined ? 'add' : 'set',
    address,
    prop,
    value,
  }))
  for (const prop of writes.removals) {
    if (attrs[prop] !== undefined) out.push({ op: 'remove', address, prop })
  }
  return out
}
```

- [ ] **Step 3: Write `ConstraintsMatrix.vue`**

Figma's control is a square with four edge bars and a centre. Clicking an edge
toggles that edge on; clicking both edges of one axis is `STRETCH`; clicking
neither is `MIN`; the centre dot is `CENTER`. Express that as a pure mapping
beside the template, so the arithmetic is testable without a DOM:

```ts
/** Which edges are lit for a constraint, and what clicking one produces. */
const EDGES: Record<PinAxis, { near: boolean; far: boolean }> = {
  MIN: { near: true, far: false },
  MAX: { near: false, far: true },
  STRETCH: { near: true, far: true },
  CENTER: { near: false, far: false },
}

/** Clicking an edge toggles it; both edges is STRETCH, neither is CENTER. */
export function toggled(constraint: PinAxis, edge: 'near' | 'far'): PinAxis {
  const next = { ...EDGES[constraint], [edge]: !EDGES[constraint][edge] }
  if (next.near && next.far) return 'STRETCH'
  if (next.near) return 'MIN'
  if (next.far) return 'MAX'
  return 'CENTER'
}
```

Give every clickable part an `aria-label` — `pin left`, `pin right`, `pin top`,
`pin bottom`, `pin centre` — because that is what the tests address and what a
screen reader needs. Follow `AlignmentMatrix.vue`'s styling tokens
(`--raised`, `--line`, `--accent`) rather than inventing new ones.

```ts
/**
 * Choosing a pin rewrites the geometry in one envelope, so the child does not
 * move. `positioningWrites` does the same for the absolute-position toggle,
 * and for the same reason: a gesture that changes what a number *means* has to
 * change the number with it.
 */
function onPinCommit(next: Pin): void {
  if (!active.value || !props.pinFrame) return
  const address = active.value.address
  const writes = pinWrites(next, props.pinFrame.box, props.pinFrame.parent)
  const constraints = { horizontal: next.horizontal, vertical: next.vertical }
  emit('patches', [
    {
      op: active.value.attrs.constraints === undefined ? 'add' : 'set',
      address,
      prop: 'constraints',
      value: constraints,
    },
    ...patchesFor(address, writes),
  ])
}
```
